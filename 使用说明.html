01

操作总览

先知道页面每块是干什么的，再照着流程走一遍。

想找逐步高亮真实控件的 Guide？请回到主页面，点标题旁的「页面 Guide」。这里保留的是分模块操作总览。

当前页面，从上到下这样看

01页头与工具条搜索、备份、分支索引、飞书同步、新增需求和版本更新。 02项目管理维护项目、MR 地址、本地路径、公共上线分支，以及单项目 MR / NB。 03未登记分支检查有提交但查不到需求登记的分支，避免漏发。 04待发版同时包含「新建」和「待发版」卡片，可勾选批量流转、拖拽排序。 05发版中 + 今日上线分支查看发版项目、当天分支状态和实际 MR 源分支，批量打开 NB。 06已发版保留发版完成记录，默认收起，需要时可恢复待发版。

一次完整的日常发版

STEP 1 · 登记需求手工新增，或从飞书项目同步。确认项目、开发分支和同发分支。
STEP 2 · 批量待发版勾选「新建」卡片，点「批量设为待发版」。
STEP 3 · 开始发版勾选「待发版」卡片，点「批量开始发版」；单条也可直接点「发版」。
STEP 4 · 建上线分支后端用批量 NB 打开当天分支页面，前端继续用 master_launched。
STEP 5 · 检查并建 MR返回后点「立即检测」，确认项目已建立，再点「打开 MR」。
STEP 6 · 完成发版GitLab 合并和实际部署完成后，再「标记已发版」或「全部发版」。
工具边界：本工具只读取分支、打开 GitLab 页面并管理本地清单，不会替你提交 MR、合并代码或执行部署。
02

启动与数据

先保证页面地址正确，再开始维护需求。

启动

双击 start-server.bat，默认打开 http://localhost:1949。无需安装前端依赖或执行构建。

更新

每天自动检查一次，有更新时页头显示绿色「有更新」，点击即可拉取。包含引擎改动时会持续显示「重启后生效」，真正重启后自动恢复版本号。

数据从哪里来

  1. 同目录存在 toDo.json 时优先加载它。
  2. 否则读取浏览器 localStorage，需求增改和状态流转会自动保存。
  3. 点「备份」把完整数据写入项目 backup/，这是防止清缓存后丢数据的推荐方式。
  4. 「导出 / 导入」适合换浏览器、换电脑或把数据交给别人。
换端口或换域名，数据看起来会像“丢了”。浏览器按「协议 + 主机 + 端口」隔离数据，localhost 与 127.0.0.1 不通用，1949 与 1950 也不通用。优先回到原来的地址。

从 v1 升级

两版使用相同默认地址和基础存储键，直接用 v2 打开 http://localhost:1949 通常即可看到旧需求、项目和公共上线分支。两版不要同时启动；切换前建议先在 v1 导出一次，再在 v2 点一次「备份」。

03

项目管理

项目配置决定 NB、MR、远端检测和分支索引能否使用。

配置项用途未配置的影响
项目名称需求关联项目的统一名称。无法从项目下拉中复用。
MR 地址生成项目 MR、NB 链接，并推导远端仓库地址。不能自动打开 MR / NB，也不能按 MR 地址检测远端分支。
本地路径读取本地提交历史、获取分支列表、计算需求关联和影响面。仍可用 MR / NB；不能计算分支索引和影响面。
公共上线分支保存当前固定上线分支或检测到的当天上线分支。开始发版时会要求填写各项目目标分支。

项目标签旁的按钮

  • MR：打开该项目的 Merge Request 页面。
  • NB：基于 master 打开新建分支页，预填 master_MMDD。单个 NB 不会启动看板自动检测。
  • 📁：悬停查看本地路径；✏️ 编辑；× 删除项目配置。

新增或编辑项目后记得保存。需求里填写项目名时，可从下拉列表直接选择已维护项目。

04

需求管理

卡片是发版清单的基本单位，状态只通过明确操作改变。

新增与编辑

  1. 点「+ 新增需求」，填写需求名称；需求链接可选，但建议填写，便于打开飞书详情和自动匹配。
  2. 逐行添加项目、开发分支和备注；📂 可从本地分支列表中选择。
  3. 依赖其他仓库一起上线时，添加「一同发版分支」。
  4. 保存后需求进入「新建」。新建和待发版可编辑，发版中和已发版需先恢复待发版。

状态与批量流转

新建→待发版→发版中→已发版
  • 批量设为待发版：勾选新建卡片，只处理选中的新建需求。
  • 批量开始发版：勾选待发版卡片，只处理选中的待发版需求，并记录同一批发版时间。
  • 混合勾选时，按钮分别显示可处理数量；没有公共上线分支时，会先要求补齐目标分支。

卡片与清单

  • 点需求名称或左侧箭头折叠单卡；「卡片展开 / 卡片折叠」只作用于当前分组。
  • 「待发版」分组同时包含新建和待发版卡片；只有这一组支持拖拽排序，拖动 ⠿ 手柄。
  • 搜索匹配需求名称、链接和分支名；搜索时卡片自动展开，清空后恢复原折叠状态。
  • 点分支名会复制分支并打开新建 MR 页；📝 查看或编辑 SQL、DDL、注意事项等备注。
  • 影响面徽标表示该分支还覆盖其他需求，悬停可查看并打开对应需求详情。
05

发版与今日上线分支

看板回答三件事：今天发哪些项目、哪些分支已存在、每个 MR 会从哪条分支创建。

今日上线分支看板

状态含义你该怎么做
未检测还没有查询过远端，不代表分支不存在。点「立即检测」。
检测中正在通过 git ls-remote 查询。等待本轮完成。
已建立该项目远端真实存在当天分支。确认 MR 源分支后打开 MR。
未建立本轮远端没有找到当天分支。打开 NB 建立，或确认是否用了别的分支名。
检测失败仓库地址、网络或凭据异常，不等于未建立。查看错误原因，处理后重试。

批量建立当天分支

  1. 点「批量建立当日上线分支」，弹窗会按项目去重，统一预填 master_MMDD。
  2. 点「打开全部新建分支页面」。浏览器允许的页面直接打开；被拦截的项目由本机引擎调系统默认浏览器补开。
  3. 你仍需在每个 GitLab 页面确认创建，本工具不会直接创建远端分支。
  4. 返回发版小助手会自动补检，也可点「立即检测」。自动检测最长持续 10 分钟，全部已建立会提前停止。
每次检测都会重新查询全部项目。远端分支被删除后，再点「立即检测」会从「已建立」更新为「未建立」，不会沿用旧成功状态；「上次检测」可用于判断结果的新旧。

MR 源分支如何确定

  • 当前项目检测到当天分支时，使用 master_MMDD。
  • 其他项目继续使用原固定上线分支，例如前端的 master_launched 或自定义固定值，不会被全局当天分支带着走。
  • 看板会直接显示「MR 源分支」，以这一列为准；目标分支为 master。

完成发版

「标记已发版」只处理当前卡片；「全部发版」会把当前所有发版中需求一起标记为已发版。它们都表示发版流程已完成，不是“开始发版”，也不会自动合并或部署。

06

分支查询与索引

「获取分支」看分支列表，「刷新分支索引」分析分支覆盖哪些需求。

获取分支

读取配置了本地路径的项目分支，按项目分组展示，可搜索、点击复制。每天首次打开会尝试后台刷新，结果有本地缓存。

刷新分支索引

分析提交记录里的需求 ID，用于自动匹配、影响面和未登记分支。项目必须同时配置 MR 地址与本地路径。

只看我的分支

默认开启，按分支首个独占提交的作者判断创建者，减少同事分支造成的噪声。需要看全部时取消勾选并重新刷新。取远端分支优先使用本地克隆的 origin 凭据，引擎不会主动弹 GitLab 登录框。

自动匹配与影响面

  • 反查：根据提交记录里的需求 ID，证据最可靠；分支名里没有需求 ID 的融合分支也能识别。
  • 分支名：根据名称推断，仅作为补充。
  • 自动匹配：把索引建议的分支追加到需求，不覆盖原有分支。
  • 影响面：提示一条分支还覆盖哪些其他需求，防止只登记其中一个需求而漏发。

点开发分支时的 MR 目标

需求状态新建 MR 的目标分支
新建test
待发版uat
发版中 / 已发版按公共固定分支、需求目标分支及当天分支检测结果确定。
07

未登记分支

专门检查“有代码提交，但没有需求登记”的漏网分支。

点「未登记分支」标题展开。面板按分支名跨项目聚合，展示涉及项目、独占提交数和最近提交日期，支持按项目或分支名搜索。

  • 需要发版：回到需求清单补充登记，或通过自动匹配挂到对应需求。
  • 无需需求：纯技术重构、环境调整等，确认后不再提示。
  • 忽略：废弃或不再关心的分支。
  • 恢复：误处置时，在已处置详情中恢复为待确认。
这个面板依赖分支索引。没有刷新索引、缺少本地路径或远端列表获取失败时，先处理面板顶部的诊断提示，不要把“没算出来”当成“没有未登记分支”。
08

飞书项目同步

只影响需求导入；不登录飞书也能使用本地分支和发版看板。

首次准备

  1. 在终端执行 meegle auth login，按提示选择空间。
  2. 用 meegle auth status 确认 authenticated: true。
  3. 打开「同步设置」，确认空间和工作项类型。未登录时窗口顶部会给出具体提示。

同步设置

  • 工作项类型可多选：同一空间可能按业务域拆成多张需求表，只选一类会漏掉其他域。
  • MQL 模板：支持 {space}、{type}、{statusFilter} 占位符。
  • 排除状态：默认 已结束,已上线，逗号分隔；系统按各类型实际支持的状态取交集。
  • 每类最多拉取：控制同步量，避免大量历史需求占满额度。

预览与导入

  1. 点「同步飞书项目」，等待各类型拉取完成。
  2. 按状态分组检查需求及自动匹配分支，可全选本组或逐条勾选。
  3. 已导入需求会标记且不能重复勾选；预览不会默认替你选中需求。
  4. 点「导入选中 N 条」，新需求进入「新建」，不会覆盖本地已有需求。
09

备份与导入导出

自动保存不等于有备份，重要发版清单请定期写入 backup。

备份（推荐）

点「备份」写入项目 backup/。点「备份记录」可查看历史、整份恢复、删除或打开目录；恢复需二次确认。

导出 / 导入

导出 JSON 用于换机或分享。导入会覆盖当前数据，操作前先备份；旧版文件缺少的新字段不会清空现有配置。

备份包含什么

  • 包含项目、需求、分支缓存、公共上线分支、分支处置、手工关联和飞书同步配置。
  • 不包含可重算的分支索引；恢复后重新「刷新分支索引」即可。
  • 卡片折叠、排序、分组展开状态只保存在本机浏览器，不随导出或备份迁移。

每天首次打开会出现备份提醒：「备份保存」优先写入项目目录，「暂不保存」当天不再提醒。

11

基础 QA

先查这里，再判断是不是功能异常。

工具会自动建分支、提交 MR、合并或部署吗？
不会。工具只读取远端分支、管理本地清单并打开 GitLab 页面。分支创建、MR 提交、合并和部署都由你在对应系统确认。
NB 和 MR 有什么区别？
NB 是 New Branch，打开新建分支页面；MR 是 Merge Request，打开合并请求页面。通常先建上线分支，再把开发分支合入上线分支，最后从上线分支向 master 创建发版 MR。
我明明建好了分支，为什么显示「未检测」？
「未检测」只表示尚未查询。单个 NB 不会自动启动检测，点看板的「立即检测」即可；检测后会显示「已建立」和最后查询时间。
删除远端分支后，为什么还显示「已建立」？
当前版本每次检测都会重新查询全部项目，包括之前成功的项目。点「立即检测」后应变为「未建立」；同时查看「上次检测」确认页面显示的是新结果。
前端也会被切到 master_MMDD 吗？
只有当前项目真实检测到当天分支时才切换。没有当天分支的项目继续使用原固定上线分支，例如 master_launched；看板「MR 源分支」列会明确显示最终取值。
批量打开只开了一个，或者打开了文档目录怎么办？
更新到当前版本并重启本地引擎后，被浏览器拦截的项目会由系统 URL 协议在默认浏览器补开，不再使用资源管理器打开 URL。若仍有个别失败，可用看板每行的「打开 NB」。
「批量开始发版」和「全部发版」是一回事吗？
不是。「批量开始发版」把勾选的待发版需求转到发版中；「全部发版」把当前所有发版中需求标记为已发版，是完成动作。
发版中发现需求信息填错了，能直接编辑吗？
发版中和已发版不允许直接编辑。先「恢复待发版」，修改后重新开始发版；恢复待发版会清除原发版时间。
没有配置本地路径，哪些功能还能用？
只要配置了 MR 地址，仍可使用 NB、MR 和远端当天分支检测。本地提交反查、影响面、自动匹配和未登记分支需要本地路径。
飞书未登录会影响发版吗？
只影响从飞书拉取需求。手工维护需求、分支查询、上线分支检测、NB / MR 和备份都可继续使用。
页面需求突然变成 0 条，是数据被删了吗？
先检查地址是否从 localhost 改成 127.0.0.1，或端口从 1949 变成其他端口；这两种情况都会读到另一份浏览器数据。再检查是否加载了同目录 toDo.json，以及是否有可恢复的备份。
导入 JSON 前要注意什么？
导入是整体覆盖，不是追加合并。先点「备份」留底，再导入。若只是增加需求，建议使用飞书同步或手工新增，不要用导入代替。
检测失败和未建立有什么区别？
「未建立」是查询成功但远端没有该分支；「检测失败」是仓库地址、网络或凭据导致查询没完成。检测失败时不能直接判断分支不存在，应按错误提示处理后重试。
更新后按钮或接口没有生效怎么办？
页面改动先刷新，必要时 Ctrl+F5。涉及 server.js 的接口改动必须重启本地引擎；更新包含引擎代码时，右上角会持续显示「重启后生效」，检测到引擎真正重启后才恢复版本号。仍异常时确认浏览器打开的是当前项目对应的端口。
