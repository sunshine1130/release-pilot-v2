需求发版管理 - 使用说明

一个前端版本发布流程管理工具，帮助团队跟踪需求的发版状态、管理项目分支、快速跳转创建 MR。

一、快速开始

文件结构

文件说明
todo-release.html主页面（HTML 模板）
todo-release.js业务逻辑（Vue 3 组件）
todo-release.css样式文件
vue.global.jsVue 3 运行库
server.js本地服务：静态页面 + 分支/飞书项目接口
toDo.json数据文件（可选，优先级高于 localStorage）
docs/技术方案与接口/算法/数据模型文档
scripts/ui-verify.mjs浏览器端自动化验证脚本（可选）

双击 start-server.bat 启动服务并自动打开页面（端口被占用时会顺延，页面会自动跟随）。无需构建工具。

数据存储优先级

  1. 同目录下的 toDo.json（如果存在，每次打开自动加载）
  2. 浏览器 localStorage（自动保存，关闭浏览器不丢失）
  3. 手动 导出/导入 JSON 文件（推荐定期备份）

v2 新增的本地键：todo_branch_index（分支索引，可重算，不导出）、 todo_branch_triage（未登记分支的处置）、todo_branch_links（手工关联）、 todo_meegle_config（同步设置）。后三个会随导出文件一起备份。

二、需求管理

需求状态流转

每条需求有 4 种状态，按以下流程流转：

新建 → 待发版 → 发版中 → 已发版

  • 新建：刚创建的需求。点击"编辑"可修改信息，"设为待发版"进入下一状态。
  • 待发版：已确认待上线的需求。点击"发版"开始发版流程，支持编辑。
  • 发版中：正在发布的需求。记录发版时间，不支持编辑。可"标记已发版"或"恢复待发版"。
  • 已发版：发版完成的需求。记录发版时间，可"恢复待发版"。

新增/编辑需求

  1. 点击 "+ 新增需求" 按钮，在表格顶部出现编辑行。
  2. 填写需求名称（必填）和需求链接（可选）。
  3. 添加涉及项目及分支名：选择项目名、填写分支名。可添加多行，使用 📂 按钮查看该项目所有分支。
  4. 添加一同发版分支：填写依赖的同步分支信息（如第三方组件分支）。只有分支名非空时才会保存。
  5. 每个分支行可添加备注（📝），记录 SQL 脚本、DDL 变更、注意事项等。
  6. 点击"保存"完成新增。新增的需求会以高亮动画显示。

点击单条需求的"编辑"按钮可修改已有需求（仅在新建/待发版状态下可编辑）。

搜索与过滤

顶部搜索框支持按以下内容实时过滤：

  • 需求名称
  • 需求链接
  • 分支名称

点击搜索框右侧 ✕ 按钮或按 Escape 清除搜索。

三、飞书项目同步（v2 新增）

前置条件：本地服务已启动，且已登录飞书项目。首次使用需在终端执行一次 meegle auth login --host project.feishu.cn（会弹出浏览器授权）。

为什么类型是「多选」

一个飞书项目空间里，「需求管理」类工作项是按业务域拆成多张独立的表的。以 ly_oms 空间为例，22 个工作项类型里有 10 个属于需求管理类：

类型名称类型名称
storyOMS需求管理tmsTMS需求管理
omsSCM需求管理bmsBMS需求管理
bdBD 需求管理ops架构&运维
wms_owms_pda_opda仓库需求管理aiAI项目需求管理
enhancements优化optimization_space优化需求管理

只勾一个类型会静默漏掉其他域的全部需求，而且不会报错。 默认已勾选所有「需求管理 / 优化」类，通常不需要改。

同步设置

  1. 点击顶部 「同步设置」。
  2. 选择空间（自动列出你有权限访问的）。
  3. 勾选需要的工作项类型（可多选）。
  4. 按需修改 MQL 模板：{space}、{type}、{statusFilter} 会被自动替换。
  5. 设置每个类型最多拉取多少条。
  6. 排除状态：逗号分隔，默认 已结束,已上线。 实测一个空间的 story 表 805 条里有 335 条已结束、412 条已上线，真正在流程中的只有 58 条 —— 不排除的话拉回来的绝大部分是废数据，还会把拉取额度占满。留空则不过滤。
  7. 点「保存」。

状态名是每个工作项类型各自一套的。例如「已上线」只在 OMS需求管理里有， SCM需求管理里没有这个状态。系统会按类型取交集后再过滤， 所以同一份排除清单用在不同类型上会自动各取所需（预览顶部会写出每个类型实际排除了什么）。

同步预览与导入

  1. 点击顶部 「同步飞书项目」，等待拉取完成。
  2. 窗口顶部显示各类型拉取情况，例如 OMS需求管理：50/58（已排除 已结束/已上线）， 分母是该类型排除后的总数。
  3. 需求按状态分组，组头显示条数与新增数，可「全选本组 / 取消本组」—— 一次只导入某一批状态的（比如只导「开发中 + 已提测」）； 点组头可收起/展开该组，收起只是少滚动，不影响已勾选的项。
  4. 每条需求显示：名称、需求ID、类型，以及自动匹配到的分支 （绿色实心＝按提交反查命中，黄色虚线＝按分支名推断）。
  5. 打开预览时不会预勾选任何需求，也不会默认打开「只看未导入」—— 筛选与勾选都由你决定。已导入的需求会标「已导入」且不可勾选。
  6. 点「全选新增」或逐条勾选，再点「导入选中 N 条」。

导入规则：只创建新需求，状态为「新建」；已存在的需求不会被覆盖， 你在本地改过的标题和分支不会被同步冲掉。

四、分支索引与未登记分支（v2 新增）

刷新分支索引

点击顶部 「刷新分支索引」，系统会分析每个项目的本地提交历史，得出「每条分支覆盖了哪些需求」。 需要项目同时配置了 MR 地址与本地路径 —— 反查依赖本地提交历史，没克隆就算不出来。

索引结果有有效期（10 分钟），过期会重算，也可以随时手动刷新。分支一直在长， 同一条分支隔几天覆盖的需求就可能变多。

「只看我的分支」（默认开启）：只分析你创建的分支。判定依据是分支首个独占提交的作者 —— 也就是分支的起点作者，而不是提交最多的人。同事的分支混进来只会污染「未登记分支」和匹配结果， 所以默认不开。关掉后会包含所有人的分支，界面会标注当前口径与过滤掉的数量。

打开「同步飞书项目」时会自动补算过期的索引，所以不需要每次先手动点一遍。

如果同步预览里每条都显示「未匹配到分支」，先看窗口顶部的提示： 它通常不是"这条需求真的没有分支"，而是索引还没生成或项目没配全（缺 MR 地址或本地路径）。 提示会明确写出是哪种情况，以及要补什么。此时每行会显示 — 而不是「未匹配到分支」，以免被误读成单条需求的事实。

需求是怎么和分支对上的

不靠分支名，靠提交记录里的需求ID（提交规范 feat(模块-需求ID): ...）。 因为大量分支根本不带需求ID，尤其是把几个需求合在一起发的「融合分支」：

分支反查出的需求
feat/ops四需求合并分支6 个需求（分支名里一个都没写）
feat/7101366806默认规则属性配置2 个需求（分支名只写了一个）

三种来源取并集，界面上用颜色区分：反查（提交证据，最可靠）、分支名（推断）、手工。

影响面提示

需求列表里，如果某条需求的分支还覆盖其他需求，分支旁边会出现橙色徽标 「还覆盖 N 个需求」，鼠标悬停可看具体需求ID。

这是为了防止漏发：融合分支很容易只被登记到一个需求名下，实际却带着好几个需求的改动。

「自动匹配」建议分支

需求行上除了你手工挂的分支，还会出现一条蓝色虚线的 自动匹配：项目 · 分支 —— 这是分支索引反查出来的、能覆盖这条需求的分支。点一下即可挂到该需求，不用自己去翻分支名。

它解决的是一个典型的「看不见」问题：一条覆盖了本需求、但没被手工挂上去的分支（融合分支最典型）， 以前在页面上完全找不到 —— 它进不了「未登记分支」（它有需求ID），也不落在任何需求行上。 已经手工挂过的分支不会再重复建议。

同一项目下已经挂了别的分支时，点建议是追加一行，不覆盖原有分支 —— 一条需求的代码同时落在同一仓库的两条分支上（融合分支 merge 了按需求命名的分支）是真实形态， 两个分支都要留在清单里。

未登记分支

「未登记分支」区列出的是有提交、但查不到任何需求登记的分支 —— 通常是因为需求还没出， 或者一堆优化都做在一个分支里。按需求拉清单发版时，这类分支最容易被整条漏掉。

  • 整个面板默认收起（标题上会显示条数），点标题展开 —— 它是需要你确认的例外，不是每天要看的主线内容。
  • 支持搜索：按分支名或项目名筛选，例如输入 mdm二期 只留这一条，输入 ops-web 只看该仓库还没登记的分支；已处置区跟着一起筛，搜一个处置过的分支也能找到并「恢复」。
  • 按分支名跨项目聚合：同名分支出现在多个仓库时只显示一张卡片，并给出涉及的仓库与提交数。
  • 无需需求：纯技术重构、组件优化、环境调整等，标记后不再提示。
  • 忽略：已废弃或不再关心。
  • 已处置的折叠在下方，点「恢复」可以重新提示。

五、发版流程

单条发版

  1. 确认需求处于 待发版 状态。
  2. 点击"发版"按钮。
  3. 如果已设置全局上线分支：直接转入发版中。
  4. 如果未设置全局上线分支：弹出窗口，为每个涉及的项目填写目标分支名（即要合并到 master 的上线分支）。
  5. 填写完成后点"确认发版"，需求状态变为 发版中。

目标分支会保存在该需求上，后续发版中的项目按钮会据此生成正确的 MR 链接。

发版中的项目 MR

在 "发版中" 分组的表头右侧，会显示当前发版涉及的项目按钮：

  • 点击项目按钮，直接跳转创建 MR（源: 上线分支 → 目标: master）。
  • 源分支的确定顺序：全局上线分支 > 发版时填写的项目目标分支 > master_launched。

全部发版

  • 发版中的需求列表旁有"全部发版"按钮，点击将所有发版中的需求标记为已发版。
  • 已发版的需求自动记录发版完成时间。

分支点击 MR 跳转

在需求列表中，点击分支名会自动复制分支名到剪贴板。如果该项目配置了 MR 地址，还会在新标签页打开 MR 创建页面：

需求状态MR 目标分支

六、项目管理

展开/折叠

点击 "项目管理" 区域可展开或折叠项目配置面板。

添加项目

在项目管理区域底部填写：

  • 项目名称（必填）
  • MR 地址（可选，填写 GitLab 项目根地址或 MR 页面地址，用于自动生成 MR 链接）
  • 本地路径（可选，填写项目在本机的绝对路径，用于获取分支列表）

按 Enter 或点击"添加"按钮。添加后项目会出现在标签列表中。

编辑/删除项目

每个项目标签右侧有 ✏️（编辑）和 ×（删除）按钮：

  • 点击 ✏️ 进入编辑模式，修改后点"保存"。
  • 点击 × 直接删除该项目。

项目快捷操作

每个项目标签旁的功能按钮：

按钮功能
MR跳转到项目的 Merge Request 列表页
NB跳转到新建分支页面（分支名自动为 master_MMDD，基于 master）
📁显示该项目配置的本地路径（鼠标悬停查看）

项目公用上线分支名

在项目管理区域底部设置全局上线分支名（如 master_launched），用于：

  • 发版中的项目按钮生成 MR（源: 此分支 → 目标: master）
  • 分支点击跳转 MR 时的目标分支回退值

按 Enter 或点击"保存上线分支"。

项目下拉选择

在新增/编辑需求时，输入项目名会自动弹出已维护的项目下拉列表：

  • 输入文字实时过滤匹配项目
  • 点击选项或上下键 + Enter 选择
  • 失去焦点后自动关闭

七、分支管理

前置条件：需要启动本地 Node.js 分支查询服务。
  1. 项目必须在"项目管理"中配置了本地路径
  2. 在终端执行 node server.js 启动服务（端口 1949）
  3. 服务启动后会向 GitLab API 请求当前用户的用户名，用于过滤个人分支

单项目分支查看

在新增/编辑需求的每个分支行，点击 📂 按钮：

  • 查看该项目所有远程分支（过滤掉 origin/ 开头）
  • 在弹窗中搜索过滤分支名
  • 点击分支名自动填充到当前分支输入框
  • 已被发版过的分支会以灰色标识（released-branch）

全部项目分支

点击顶部 "获取分支" 按钮：

  • 为所有配置了本地路径的项目获取最近分支列表
  • 结果以弹窗展示，按项目分组
  • 支持全局搜索过滤
  • 点击分支名直接复制到剪贴板

分支缓存

  • 获取分支后自动缓存到 localStorage，下次打开直接使用缓存
  • 每天首次打开页面时，自动后台静默刷新全部分支（当天已刷新则跳过）
  • 顶部有进度条显示刷新状态

八、备注功能

为分支添加备注

  • 在编辑模式下，每个分支行有 📝 按钮，点击打开备注编辑弹窗。
  • 备注内容可记录 SQL 脚本、DDL 变更、注意事项等。
  • 有备注的分支行 📝 按钮会高亮显示（has-notes 样式）。
  • 在查看模式下，如果有备注则显示 📝 按钮，点击可查看但不可编辑。

右键菜单

在待发版和新建需求的分支行上点击右键：

  • 📝 添加/编辑备注
  • 🗑️ 清除备注（仅当已有备注时显示）

九、导入导出

导出

  • 点击顶部 "导出" 按钮。
  • 生成 JSON 文件：todoList-发版需求-时间戳.json
  • 包含完整数据：项目列表、需求列表、分支缓存、上线分支设置。

导入

  • 点击顶部 "导入" 按钮，选择之前导出的 JSON 文件。
  • 导入会覆盖当前所有数据并自动保存。
  • 导入后自动清除编辑状态和新增行。

每日备份提醒

每天首次打开页面时，弹出备份提醒窗口：

  • "导出保存" — 自动导出 JSON 文件并关闭提醒
  • "暂不保存" — 关闭提醒（下次打开不再弹出当天）
